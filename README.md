# Enterprise Support Agent

Production-ready B2B AI Support Agent built with FastAPI, LangGraph, and PostgreSQL/pgvector. The service provides persistent conversation memory, retrieval-augmented generation (RAG) over internal documentation, structured tool execution, and real-time token streaming via Server-Sent Events (SSE).
```

## Quick Start

### 1. Environment Setup

Copy the example environment file and configure your credentials (`LLM_API_KEY` for Groq or any OpenAI-compatible provider, and `POSTGRES_PASSWORD`):

```bash
cp .env.example .env

```

### 2. Build and Run

Start the stack using Docker Compose. Database migrations run automatically on API container startup:

```bash
docker compose up --build

```

### 3. Ingest Knowledge Base

Load the sample documentation into the `pgvector` store (safe to re-run; upserts by deterministic document IDs):

```bash
docker compose exec api python -m scripts.ingest_kb kb_docs/

```

Interactive API documentation (Swagger UI) is available at `http://localhost:8000/docs`.

## API Usage

### Standard Chat (Non-Streaming)

```bash
curl -s http://localhost:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "thread_id": "demo-1",
    "message": "How long do refunds take for a Starter plan customer?"
  }'

```

### Streaming Chat (Server-Sent Events)

```bash
curl -N http://localhost:8000/api/v1/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{
    "thread_id": "demo-1",
    "message": "And what about Enterprise?"
  }'

```

### Retrieve Thread History

```bash
curl -s http://localhost:8000/api/v1/threads/demo-1/history

```

## SSE Event Contract

The `/api/v1/chat/stream` endpoint streams events in standard `text/event-stream` format:

| Event | Payload Schema | Description |
| --- | --- | --- |
| `token` | `{"text": "..."}` | Incremental answer token generated by the LLM. |
| `tool_start` | `{"name": "crm_lookup"}` | Emitted when the agent invokes a tool. |
| `tool_end` | `{"name": "crm_lookup"}` | Emitted when tool execution completes. |
| `done` | `{"thread_id": "...", "tool_calls_used": 1, "sources": ["refund_policy.md"]}` | Terminal success event containing execution metadata and cited KB sources. |
| `error` | `{"detail": "..."}` | Terminal error event (emitted if an exception occurs after streaming begins). |

**Notes on Streaming & Concurrency:**

* Keep-alive comments (`: ping`) are sent periodically to prevent proxy idle timeouts and should be ignored by clients.
* Concurrent requests targeting the same `thread_id` are serialized via PostgreSQL advisory locks. If a thread is currently locked, `/chat` returns `409 Conflict` and `/chat/stream` emits an `error` event.

## Frontend Integration Example

Because the native browser `EventSource` API does not support `POST` requests, use the `fetch` API with a readable stream. Configure `CORS_ALLOW_ORIGINS=["http://localhost:3000"]` in `.env` if serving the frontend from a separate origin.

```javascript
async function chatStream(threadId, message, { onToken, onEvent, signal }) {
  const res = await fetch("http://localhost:8000/api/v1/chat/stream", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ thread_id: threadId, message }),
    signal, // AbortController: aborting immediately stops the server-side graph run
  });

  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`); // Request validation errors (422) arrive here
  }

  const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = "";

  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += value;
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {
      const frame = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);

      if (frame.startsWith(":")) continue; // Ignore keep-alive pings

      const event = /^event: (.*)$/m.exec(frame)?.[1];
      const data = JSON.parse(/^data: (.*)$/m.exec(frame)[1]);

      if (event === "token") onToken?.(data.text);
      onEvent?.(event, data); // Handles tool_start, tool_end, done, error
    }
  }
}

```

## Testing

Install development dependencies and run the offline test suite (uses a scripted fake LLM and deterministic hash-based embeddings; requires no external API keys or network access):

```bash
pip install -r requirements-dev.txt
pytest

```

### Integration Tests

Integration tests (`-m integration`) validate Alembic migrations, HNSW index usage, checkpointer persistence across restarts, advisory locks, and end-to-end SSE streaming against PostgreSQL with `pgvector`:

```bash
# Point to an existing Postgres instance with pgvector enabled
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/test_db pytest -m integration

```

If `TEST_DATABASE_URL` is omitted, the suite attempts to spin up an embedded server via `pixeltable-pgserver` (if installed) or skips integration tests automatically.

## Engineering Notes & Production Checklist

* **Embeddings Model:** Uses local `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions) because Groq does not expose an embeddings endpoint. Vector dimensions are fixed in Alembic migration `0002`; changing embedding models requires a new migration and full re-ingestion.
* **Prompt Injection Mitigation:** Retrieved knowledge-base passages are treated as untrusted data, wrapped in XML delimiter tags by the retrieval tool, and explicitly isolated from system instructions.
* **Connection Pooling:** The LangGraph checkpointer uses a dedicated `psycopg` async connection pool separate from the `pgvector` SQLAlchemy engine to prevent pool exhaustion under load.
* **Security & Persistence:** Before deploying to a public environment, add an authentication dependency (API key or JWT verification) to FastAPI routes and migrate the in-memory CRM/ticket stores in `agent/tools.py` to persistent database models.
